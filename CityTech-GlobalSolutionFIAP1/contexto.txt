1. O que é o CityTech?
O CityTech — Plataforma Inteligente de Monitoramento e Zeladoria Urbana é um sistema voltado à identificação, ao registro e ao acompanhamento de problemas urbanos.
A proposta é conectar cidadãos e gestores públicos por meio de uma plataforma digital que facilite a comunicação e o acompanhamento das ocorrências.
Exemplos de problemas que o sistema pode atender incluem buracos nas ruas, postes com iluminação danificada, descarte irregular de lixo e problemas de infraestrutura pública.
O cidadão poderá registrar uma ocorrência, acompanhar seu andamento e visualizar as informações relacionadas à solução do problema. O gestor poderá organizar as ocorrências, atualizar seus status, consultar indicadores e analisar sugestões de classificação geradas por IA.
2. Arquitetura do sistema
Frontend — Aplicativo React Native
Telas, navegação, cadastro, login e gerenciamento de ocorrências
Backend .NET
Contas, autenticação JWT, acompanhamentos e SQL Server
Backend Java
Ocorrências, categorias, gestão, Oracle, IA e RabbitMQ
É importante que o integrante compreenda que Java Advanced e .NET são disciplinas diferentes, embora ambas façam parte do mesmo CityTech.
Para a disciplina Mobile, a FIAP exige um CRUD real consumindo a API Java ou .NET. Nossa arquitetura prevê a utilização dos dois serviços conforme as funcionalidades, mas o aplicativo não precisa duplicar responsabilidades.
3. Funcionalidades do frontend
O aplicativo deve permitir que o usuário se cadastre, faça login, consulte ocorrências urbanas, registre problemas e acompanhe suas solicitações.

Essa é uma organização sugerida, não uma obrigação de implementar todas as telas.
A FIAP exige no mínimo seis telas distintas, e a tela Sobre o App não conta nesse total.
4. Identidade visual
O CityTech deve transmitir a ideia de tecnologia, confiança, organização e utilidade pública.
Minha sugestão para o integrante é desenvolver uma interface moderna e profissional, com hierarquia visual clara, tipografia legível, navegação simples e componentes reutilizáveis.
O foco deve estar na facilidade de registrar uma ocorrência e entender seu andamento, sem transformar o aplicativo em algo excessivamente complexo.
A identidade visual ainda pode ser definida pelo integrante do frontend, desde que seja consistente em todas as telas.
